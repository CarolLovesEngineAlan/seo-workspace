# PRD：/create Use-Case 页面前后端分离方案

## 1. 背景与目标

### 问题

现有 `/create` use-case 页面未被搜索引擎收录。根本原因是**内容太薄**——页面主体是视频展示，文字极少，搜索引擎无法判断页面价值。同时，页面强依赖 12 条视频素材才能上线，导致发布节奏完全被视频产能卡死。

### 目标

1. **解决收录问题**：页面有足够的文字内容，无论视频是否就位都能被收录
2. **解耦视频与发布**：视频模块可选，有则展示，无则不影响上线
3. **SEO 自主发布**：接入 CMS，SEO 无需等工程排期即可创建和更新页面

---

## 2. 页面结构设计

参考 Canva `/create` 风格：以富文本正文为页面主体，视频作为补充展示模块。

```
/create/[slug]
│
├── 【固定】页面 Header
│   ├── H1 标题（主关键词）
│   ├── 副标题/描述文字
│   └── CTA 按钮
│
├── 【富文本】正文内容区  ← 主体，决定 SEO 收录
│   └── 由编辑器统一管理（H2/H3、段落、列表、图片、内链等）
│
├── 【可选】视频素材模块  ← 独立管理，有则渲染，无则不占位
│   └── 视频卡片网格（标题 + 封面图 + 视频链接）
│
└── 【固定】页面 Footer
    └── CTA + 内链导航
```

**关键设计原则：**
- 视频模块与正文完全解耦，视频未就位时页面正常上线
- 正文富文本足够丰富，保证搜索引擎可收录
- 视频素材跨页面独立管理，可被多个页面引用

## 3. CMS 内容模型

### 3.1 页面基本信息（Page Metadata）

| 字段 | 类型 | 说明 |
|---|---|---|
| `slug` | string | URL 路径，如 `social-media-marketing` |
| `title` | string | H1 标题，包含主关键词 |
| `subtitle` | string | 副标题/描述 |
| `meta_title` | string | SEO title（不填则默认用 title） |
| `meta_description` | string | SEO meta description，150 字以内 |
| `cta_text` | string | 主 CTA 按钮文案 |
| `cta_url` | string | 主 CTA 跳转链接 |
| `status` | enum | `draft` / `published` |

### 3.2 正文内容区（Rich Text Body）

| 字段 | 类型 | 说明 |
|---|---|---|
| `body` | rich_text | 富文本编辑器，支持 H2/H3/段落/列表/图片/内链/代码块 |

**编辑器要求：**
- 所有非视频的内容板块（介绍文案、使用场景、FAQ、功能说明、内链模块等）全部在此编辑
- 不单独拆分为独立字段，保持编辑自由度
- 支持插入图片（上传或外链）
- 支持插入内链锚文本

### 3.3 视频素材模块（Video Module）— 独立管理

视频素材**不存储在页面内容模型中**，而是独立一张表，通过 `page_slug` 关联到页面。

**视频素材表（`video_assets`）：**

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | uuid | 主键 |
| `page_slug` | string | 关联的页面 slug，支持多个页面引用同一条 |
| `title` | string | 视频标题（展示用） |
| `cover_image` | string | 封面图 URL |
| `video_url` | string | 视频链接（CDN / YouTube / 内部存储） |
| `sort_order` | integer | 展示顺序 |
| `status` | enum | `active` / `hidden` |

**调用规则：**
- 前端渲染时按 `page_slug` 查询，有记录则渲染视频模块，无记录则不渲染、不占位
- 同一条视频素材可被多个页面引用（如"产品广告"视频同时出现在 `product-video` 和 `social-media-marketing` 页面）
- 视频素材上传/管理走独立管理界面，与页面编辑完全分离

## 4. 前后端分离架构

```
CMS（内容侧，SEO 自主操作）
│
├── 页面编辑器
│   ├── 基本信息填写（slug / title / meta）
│   └── 富文本编辑器（正文所有板块）
│
└── 视频素材管理（独立模块）
    ├── 上传 / 编辑 / 排序视频素材
    └── 绑定到指定 page_slug

          ↓ API / CMS SDK

Next.js 前端（工程侧，只做一次模板）
│
├── /create/[slug] 页面模板
│   ├── 读取页面基本信息 → 渲染 Header + Meta
│   ├── 读取 body rich text → 渲染正文
│   └── 读取 video_assets（按 slug 查询）
│       ├── 有数据 → 渲染视频模块
│       └── 无数据 → 跳过，不渲染
│
└── ISR / SSG 静态生成（对 SEO 友好）
```

**工程只需做一次：**
- 建立 `/create/[slug]` 动态路由模板
- 对接 CMS API 读取页面内容
- 对接 `video_assets` 查询逻辑
- 实现视频模块的条件渲染

**此后 SEO 可以：**
- 在 CMS 中新建任意 slug 的 use-case 页面
- 编辑富文本正文，当天发布
- 随时为页面添加/移除视频素材，不影响页面发布状态

---

## 5. 发布策略

| 场景 | 操作 | 页面状态 |
|---|---|---|
| 视频未就位，内容已写好 | 直接发布，不绑定视频 | 正常上线，正常收录，无视频模块 |
| 视频就位后 | 在视频素材管理中上传并绑定 slug | 视频模块自动出现，无需改动页面 |
| 需要替换视频 | 在视频管理中更新，不需要发布新页面版本 | 实时生效 |
| 多个页面共用同一视频 | 绑定多个 slug | 一次上传，多处复用 |

## 6. 工程投入估算

| 工作项 | 负责方 | 预估投入 |
|---|---|---|
| CMS 中新增 use-case 内容模型（基本信息 + 富文本字段） | 工程 | 1～2 天 |
| 新增视频素材独立表及管理界面 | 工程 | 1～2 天 |
| `/create/[slug]` 前端模板（对接 CMS + 视频条件渲染） | 工程 | 2～3 天 |
| SEO 迁移现有页面内容至 CMS | SEO | 1 天 |
| **合计** | | **约 5～8 天** |

---

## 7. 验收标准

- [ ] SEO 可在 CMS 中新建一个 use-case 页面，不需要工程介入
- [ ] 新建页面（无视频）可正常上线，无视频模块区域
- [ ] 绑定视频素材后，视频模块在页面中自动出现
- [ ] 移除视频绑定后，页面回到无视频状态，正文不受影响
- [ ] 同一条视频素材可同时绑定到两个不同 slug 的页面
- [ ] 页面 meta title / meta description 可独立编辑
- [ ] 富文本正文支持 H2、H3、段落、列表、图片、超链接

---

## 8. 本方案不包含

- Gallery（`/make`）页面——作品展示逻辑不同，独立规划
- `/features`、`/compare`、`/guide` 等其他页面类型——内容模型不同，独立规划
- 视频素材的自动生成或 AI 辅助——仅管理已有素材
